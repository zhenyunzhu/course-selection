## 三、冒烟测试顺序（照着打，5 分钟）

用 Apifox 或 curl 都行。**注意所有请求都走 8088**。

### 1. 登录拿 token

```http
POST http://localhost:8088/api/auth/login
Content-Type: application/json

{"studentId":1001,"name":"张三"}
```

```json
{"code":0,"data":{"token":"8f3a...","studentId":1001,"name":"张三"}}
```

后面所有请求都带：`Authorization: Bearer <token>`

### 2. 看课程和教学班

```http
GET http://localhost:8088/api/courses
GET http://localhost:8088/api/courses/3/classes
```

注意 `classId=3`（数据结构）的 `remain` 是 **2**，专门用来演示抢满。

### 3. 选课（成功）

```http
POST http://localhost:8088/api/enrollments
Authorization: Bearer <token>
X-Idempotent-Token: 任意 uuid，每次换一个
Content-Type: application/json

{"classId":2}
```

> 先选 `classId=2`（线性代数），因为 `classId=3`（数据结构）要求先修线性代数。

### 4. 验证四条规则

| 操作 | 期望 |
|---|---|
| 同一个 `X-Idempotent-Token` 再发一次 | `3001` 请勿重复提交 |
| 再选 `classId=4`（同为数据结构，另一个班） | `3001` 已选过该课程 |
| 没修线性代数就选 `classId=3` | `3004` 未满足先修 |
| 已选线性代数后选 `classId=9`（时间冲突） | `3003` 时间冲突 |

### 5. 退课与容量回补

```http
DELETE http://localhost:8088/api/enrollments/{enrollNo}
```

再查 `GET /api/courses/3/classes`，`remain` 应该 +1。

### 6. 对账

```http
POST http://localhost:8082/internal/reconcile
```

返回 `{"released":0}` 表示当前没有悬挂预占。

## 四、看数据库确认「真的发生了」

```sql
-- 预占记录（0 预占中 / 1 已确认 / 2 已取消 / 3 超时释放）
SELECT reserve_id, class_id, student_id, status, expire_time
FROM cs_course.t_capacity_reserve ORDER BY create_time DESC LIMIT 10;

-- 容量
SELECT id, capacity, remain FROM cs_course.t_class;

-- 选课单
SELECT enroll_no, student_id, course_id, status FROM cs_enroll.t_enrollment;

-- Outbox（0 待投递 / 1 已投递 / 2 死信）
SELECT id, biz_type, biz_key, status, retry_count FROM cs_enroll.t_outbox_message;
```

**调完一次选课，这四张表都要看一眼**，你才知道代码到底动了什么。

## 五、常见错误

| 现象 | 原因 | 解决 |
|---|---|---|
| 编译报「找不到符号 getCode」 | 用了 JDK 26 | 切 `JAVA_HOME` 到 JDK 17 |
| 401 / 连不上 8088 | 网关没起来 | 看 `logs/gateway.log` |
| `500` + `NoResourceFoundException` | 路径写错（少了 `?` 或方法不对） | 对照接口清单 |
| `2003` 容量不足 | 教学班的 `remain` 是 0 | `UPDATE cs_course.t_class SET remain=capacity` |
| `3004` 先修不满足 | 顺序选错了 | 先高数 → 线代 → 数据结构 |
| 中文乱码 | mysql 客户端默认 GBK | 导入时加 `--default-character-set=utf8mb4` |
| 端口占用 | 上次没停 | `.\stop.ps1` |

## 六、改代码的实验（真的做一遍才算懂）

1. **把预占 TTL 改成 30 秒**：`cs-course/application.yml` 的 `cs.reserve.ttl-seconds`，重启后选课但**不发 confirm**（可以临时注释掉 ⑥），看 30 秒后 `status` 变成 3、`remain` 回补
2. **把对账注释掉**：观察容量永久泄漏——你就明白对账不是可选项
3. **把 `deduct` 改成先查后减**：并发压一下，观察超卖——你就明白为什么必须条件更新
4. **把网关白名单加一个 `/api/enrollments`**：直接调下游，观察 `X-Student-Id` 缺失时的 1010
